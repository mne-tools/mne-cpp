# BrainRenderer

**Namespace:** `DISP3DLIB` &nbsp;·&nbsp; **Library:** 3D Display Library &nbsp;·&nbsp; **Source:** [`disp3D/view/brainrenderer.h`](https://github.com/mne-tools/mne-cpp/blob/staging/src/libraries/disp3D/view/brainrenderer.h)

`#include <disp3D/brainrenderer.h>`

```cpp
class DISP3DLIB::BrainRenderer
```

[`BrainRenderer`](/docs/api/disp3-d/brain-renderer) handles the low-level RHI rendering logic, managing pipelines, shaders, and draw calls for brain surfaces.

Qt RHI-based 3-D renderer managing scene objects, lighting, camera, and render pipeline for brain visualization.

### ensureRenderTargets(rhi, colorTex, pixelSize)

Create the dual render-target pair for multi-pass rendering.

Both render targets share the same color texture and depth-stencil buffer but differ in their load/store flags:

- m_rtClear: clears color+depth on beginPass (first pass)
- m_rtPreserve: preserves previous output (passes 2+)

Qt bakes these flags into native resources at create() time, so calling setFlags() dynamically does NOT work (especially on WebGL). This is the validated pattern from test_wasm_multi_pass.

**Parameters:**

- **rhi** : *QRhi **
  QRhi instance.

- **colorTex** : *QRhiTexture **
  Color texture (owned by QRhiWidget or caller).

- **pixelSize** : *const QSize &*
  Render target dimensions.

### newFrame()

Start a new frame: frees all per-draw uniform slots.

Call before the frame's first prepare call.

A frame is recorded in two phases. First every prepare*() call writes its uniforms and uploads into resource update batches. Then `beginFrame()` commits them, and the issue*() calls only bind and draw: QRhi forbids resource updates inside a render pass, and prepare calls made inside one are rejected with a warning.

The renderer owns the GPU copies of the renderables' streams. They are created on the first draw, updated when a stream's generation changes, and freed once the renderable is destroyed or has not been drawn for a while.

## Example

No example of its own: QRhi draw backend owned privately by BrainView; it needs a live GPU device and is driven only through BrainView.

It is exercised by:

````cpp title="src/examples/ex_disp3d_scene/main.cpp"
BrainView view; // QRhi widget; nothing is rendered until it is shown
view.setViewCount(2);
const bool twoPanes = view.viewCount() == 2 && view.viewMode() == BrainView::MultiView;
LiveMarker trackerTip;
trackerTip.position = QVector3D(0.0f, 0.08f, 0.04f);
trackerTip.color = Qt::yellow;
view.setLiveMarkers({trackerTip}); // transient, does not move the camera
view.clearLiveMarkers();
view.setViewCount(1);
````
